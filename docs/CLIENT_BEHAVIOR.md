## 현재 WPF 클라이언트의 기록 동작

> 📦 원래 README "현재 WPF 클라이언트의 기록 동작"에 있던 내용입니다.

- 같은 Windows 사용자·로그인 세션에서는 알통을 하나만 실행한다. 다시 실행하면 새 프로세스는 수집·DB 초기화 없이 종료하고 기존 창을 표시하며, 최소화된 창은 복원한다. Debug·Release 실행도 같은 잠금을 사용한다.
- 활동 기록의 시작·마치기는 하나의 활동 범위를 정한다. 앱별 사용시간과 알림 저장·리포트 집계는 활동 기록 중 집중모드 ON인 구간을 기준으로 한다. 휴식 단계도 집중모드 ON이면 포함한다.
- 대시보드의 활동 경과 시간은 집중모드 OFF에서도 흐른다. 앱 종료·절전 등 관측하지 못한 공백은 기록 시간에서 제외하며, 재실행하면 진행 중인 활동을 복원한다.
- 기록을 마치면 결과 리포트를 열고 현재 활동 일지·앱별 사용시간 화면은 비운다. DB의 완료 기록은 보존하며, 최근 결과를 다시 열 때 저장 데이터로 재집계한다. 집중모드를 끄는 것만으로는 활동 리포트를 만들지 않는다.
- 집중모드의 기본 방식은 알통 자체 제어다. 등록된 알림 발신자 중 일반 앱을 기본 선택하고, 설정에서 앱을 제외하거나 새로 조회한다. 새로 발견된 앱은 기본 선택하며, 제외 선택은 재실행 후에도 유지한다. 집중 중에는 선택을 잠그고 다음 집중부터 변경을 적용한다.
- 앱 선택 설정 `notification-control.json`이 손상되면 원본을 같은 폴더의 `.corrupt-<식별자>.json` 사본으로 보관하고 Windows 방식으로 초기화한다. 제외 앱 정보가 사라졌으므로 사용자가 자체 제어로 다시 전환하기 전에는 자체 차단을 시작하지 않는다. 사본 보관·초기화 또는 파일 읽기에 실패하면 원본을 유지하고 해당 실행에서는 Windows 방식을 사용한다. 원래 알림 값을 담은 `notification-recovery.json`은 별도 복구 자료이므로 손상됐다고 초기화하거나 삭제하지 않는다.
- 설정 화면은 기존 집중·휴식 루틴, 알림과 시스템 카드 아래에 **알통 자체 방해금지 · 프로토타입** 카드를 마지막으로 배치한다. 새로 추가한 방식 전환·앱 조회·설정 복구·앱 선택은 이 카드에 모으고, 기존 루틴 알림·알림 확인·앱 종료 버튼과 버전은 알림과 시스템 카드에 유지한다. 앱 목록에 별도 스크롤 영역을 두지 않고 설정 화면 전체를 하나의 세로 스크롤로 탐색한다.
- 자체 제어는 Windows 표준 알림의 앱별 배너·알림음만 변경한다. 알림 수신 허용, 알림센터 보관, 기록 삭제, Windows 전체 알림 설정은 변경하지 않는다. Windows 시스템·보안 발신자, 앱 정보가 유효하지 않은 항목, 알림 또는 알림센터 보관이 꺼진 앱은 내부에서 보호·제외하며 사용자 설정 목록과 앱 개수에서는 숨긴다. 설정에는 제어 가능한 앱만 표시하며, 사용자가 체크를 해제한 앱은 다시 선택할 수 있도록 목록에 남긴다. 카카오톡은 기존 전용 인터셉터와 집중 중 음소거·종료 시 음소거 해제를 두 방식 모두에서 유지한다.
- 방해금지 구현은 수집기와 독립적이다. 팀원 1의 기존 `WinRtNotificationListener`·`KakaoNotificationInterceptor` → `CompositeNotificationListener` → `NotificationPipelineCoordinator` → 미니바 전달 경로와 데이터 형식을 유지한다. 특정 WinRT 수집기의 권한이나 모의 파이프 여부를 자체 집중의 시작·종료 조건으로 사용하지 않는다. 수집기 자체의 권한 요청·패키지 등록·모의 수신 대체 동작은 기존 구현이 담당한다. 기존 수집·파이프라인의 개발 로그도 유지한다.
- 자체 집중 시작 전에는 원래 설정 백업과 별도 복구 감시 프로세스를 준비한다. 집중 중 복구 감시가 중단되면 설정 복구 후 집중을 종료한다. 수집 준비 상태는 방해금지 성공 여부와 별개이므로, 배너 억제와 실제 수집·미니바 전달은 각각 검증한다.
- 변경 전 원래 값과 레지스트리 값 존재 여부·형식을 `%LOCALAPPDATA%/Altong/notification-recovery.json`에 저장한다. 정상 종료·강제 종료 감시·다음 실행에서 복구한다. 재부팅/로그오프로 감시 프로세스도 종료되면 다음 앱 실행 시 복구하며, 앱을 다시 실행하기 전 즉시 복구를 보장하지는 않는다. 사용자가 별도로 변경한 값은 덮어쓰지 않는다. 복구 실패 파일은 보존하고 복구 버튼으로 재시도한다.
- 집중 중 앱 삭제로 알림 발신자 등록이 사라지면 해당 항목은 복구 대기 목록에서 정리하고, 남은 앱의 설정을 계속 복구한다. 삭제된 발신자 설정은 다시 만들지 않는다. 등록 확인의 접근 권한 오류나 COM 오류는 삭제로 간주하지 않고 백업을 보존한다.
- 자체 제어는 공개 Windows API가 아닌 빌드 한정 COM 어댑터다. 현재 노트북 Windows 11 25H2, build 26200.9711의 `NotificationController.dll` SHA256 `3242604B327A90314F88F044FFA4E3B8B2DD28F7D9E7009AB38793ABFE6FFC2D`에서만 활성화한다. 업데이트로 DLL이 바뀌면 쓰기를 차단한다. 다른 Windows 10/11 호환성은 검증하지 않았다. 소리 필드 적용·복구 확인과 별개로 실제 음향 재생 여부는 로컬 청취 검증이 필요하다.
- 설정의 임시 비교 버튼으로 **알통 자체 제어 / 기존 Windows 방식**을 전환한다. 전환 전 자체 설정을 복구하고 현재 집중을 종료한다. Windows 방식은 기존처럼 설정 화면을 안내하고 Windows 방해 금지 상태를 따른다. 자체 방식에서는 Windows 상태가 바뀌어도 집중은 바뀌지 않는다. Windows 방해 금지가 이미 켜져 있다면 자체 제어와 무관하게 Windows가 배너를 숨길 수 있다.
- 과거 기록 중 집중모드 구간 정보가 없는 기록은 기존 방식으로 표시한다.

## 상단 노치와 알림 패널

> 기존 가로·기존 세로·라벤더 미니바는 상단 노치로 대체했습니다. 이전 구현은 `chore/minibar-backup` 브랜치에 남아 있습니다.

집중 모드를 켜면 주 모니터 맨 위 띠 가운데에 검은 노치가 나타나고, 노치에 마우스를 올리면 노치가 아래로 늘어나 알림 패널이 됩니다.
노치 클릭 또는 알림 패널의 대시보드 버튼은 대시보드가 이미 활성화되어 있으면 최소화합니다. 다른 창을 보고 있거나 대시보드가 숨겨져 있으면 표시·활성화하며, 최소화된 창은 복원합니다.
안내 말풍선은 노치 아래에 두고 위쪽 화살표가 노치 가운데를 가리킵니다. 안내는 X 버튼 대신 말풍선 어디를 눌러도 닫힙니다. 제목 오른쪽에 **어디든 눌러 닫기**를 표시하고, 마우스를 올리면 말풍선 전체 배경이 은은하게 바뀝니다. 안내를 닫아도 집중 세션 상태는 바뀌지 않습니다.

### 띠

- 주 모니터 맨 위에 높이 30의 띠를 Windows AppBar로 예약합니다. 띠 영역에는 다른 창이 들어오지 않아 최대화한 창도 띠 아래부터 그려집니다. 띠는 노치가 보이는 동안(집중 모드 ON)에만 예약하고, 집중 모드를 끄면 바로 해제해 화면 위쪽 공간을 돌려줍니다. 이때 최대화한 창의 높이가 띠 높이만큼 바뀝니다. 띠 예약은 앱(App)만 켜며, 테스트·도구에서 노치 창을 띄울 때는 예약하지 않습니다.
- 패널 하단의 **상단 띠: 검정 · 배경색**으로 띠 색을 고릅니다. 기본은 배경색입니다. 검정(`#000000`)을 고르면 접힌 노치가 띠와 이어져 표시등만 보입니다. 배경색은 바탕화면 그림 위쪽 6% 높이의 평균색을 불투명하게 칠하며, 바탕화면 그림이 없으면 단색 배경색을, 둘 다 읽지 못하면 검정을 씁니다. Windows 설정에서 바탕화면을 바꾸면 바로, 슬라이드 쇼·단색 변경처럼 알림이 없는 경우에도 2초 안에 자동으로 다시 맞춥니다(그림 파일의 경로·수정 시각·크기를 비교). 그림을 쓰는 중이라 읽지 못하면 이전 색을 유지하고 다음 확인에서 다시 읽습니다. 검정일 때는 확인하지 않습니다. 그림의 맞춤 방식은 따지지 않고 원본 그림의 위쪽을 기준으로 합니다. 띠 색 선택은 현재 실행 중에 유지됩니다.
- AppBar 등록에 실패하면 띠를 숨기고 노치만 표시합니다. 탐색기가 다시 시작되면 다시 등록합니다. 띠는 항상 노치 창 바로 아래 z-순서에 두어 노치를 덮지 않습니다.
- 띠 영역은 다른 앱 창이 넘지 못합니다.
  - 띠가 생길 때 띠에 걸친 창을 띠 바로 아래로 내립니다. 아래가 작업표시줄을 넘으면 높이를 줄이며, 120px보다 작게 줄이지는 않습니다.
  - 창의 제목 표시줄이나 위쪽 테두리·모서리를 잡고 끄는 동안에는 커서가 띠 아랫선에서 멈춥니다. 커서가 작업 영역 맨 위에 닿아야 Windows 11 스냅 레이아웃 막대가 열리므로, 끄는 동안에는 제목 표시줄을 잡은 높이만큼 창이 띠 밑으로 들어갈 수 있고 놓으면 띠 아래로 내립니다. 아래쪽·옆 테두리 크기 조절은 막지 않습니다. 마우스 버튼을 떼면 바로 풉니다.
  - 키보드 이동이나 앱이 직접 창을 옮기는 경우처럼 커서를 가둘 수 없으면, 이동이 끝나거나 창이 앞으로 나올 때 띠 아래로 내립니다.
  - 최대화·최소화·전체화면 창, 도구 창, 맨 위 고정 창, 보조 모니터 창, 알통 창은 건드리지 않습니다. 관리자 권한으로 실행된 창은 Windows 보안 정책상 옮길 수 없습니다. 주 모니터 위쪽에 다른 모니터가 있으면 그쪽으로 옮기는 것을 막지 않도록 커서를 가두지 않습니다. 띠를 해제해도 내린 창을 원래 위치로 되돌리지 않습니다.

### 노치

- 노치는 위쪽 폭 360, 아래쪽 평평한 폭 235, 높이 30의 검은 도형이며, 양옆은 짧은 오목 어깨에서 비스듬히 내려와 둥글게 바닥으로 이어집니다. 팀 시안 윤곽을 측정해 3차 베지어로 맞췄습니다. 테두리선 없이 띠보다 어두운 색으로만 구분합니다.
- 평소 작은 표시등만 표시하며, 긴급도 5의 미확인 알림이 있을 때만 표시등 옆에 전체 미확인 개수를 표시합니다. 집중 상태 툴팁(예: 집중 중)은 띄우지 않습니다.
- 커서를 올리거나 알림 패널이 열린 동안에는 화면 끝에 닿는 위쪽 변을 뺀 윤곽을 은색 1px 선(`#C4C8D0`, 불투명도 0.55)으로 드러냅니다. 0.12초에 나타나고 0.16초에 사라지며 빛 번짐은 쓰지 않습니다. 노치 폭은 바꾸지 않습니다.
- 좌우로 드래그하면 띠 안에서 옮겨지며 위치는 현재 실행 중에 유지됩니다. 노치는 화면 밖으로 나가지 않습니다.
- 집중을 켜서 노치가 나타날 때는 **집중 모드가 켜졌어요** 말풍선을 띄우지 않고, 청록(`#72B5A6`)·라벤더(`#A99BE0`) 색 물결(일렁임)이 노치 안을 왼쪽에서 오른쪽으로 약 3.5초에 한 번 천천히 흘러 켜졌음을 알립니다. 반복하지 않고 끝나면 검은 노치로 돌아옵니다. 집중 종료 때도 말풍선을 띄우지 않고 노치와 띠가 바로 사라집니다. 휴식 시작·집중 시간 종료 안내는 노치 아래 말풍선으로 보이며, 이때도 일렁임을 한 번 재생합니다.

### 알림 패널

- 커서를 노치에 0.5초 올리면 패널이 열립니다. 노치와 패널은 한 창 안에 한 윤곽 도형으로 그려, 펼치는 동안 두 부분이 어긋나거나 이음매가 생기지 않습니다. 창의 왼쪽 위는 노치 위치로만 정해지며(상세 자리까지 늘 포함), 패널을 열 때만 창을 아래로 늘리고 닫힌 뒤 다시 줄입니다. 그래서 창 크기가 바뀌는 순간에도 노치가 흔들리지 않고, 닫혀 있을 때는 투명 창을 작게 유지합니다.
- 여는 동작은 하나의 진행값(0.4초, 일정한 속도)으로 묶습니다. 앞부분(42%)에서 노치 바닥이 목록 폭(316)까지 넓어지며, 옆선은 바닥에서 수평으로 끝나는 S자에서 띠부터 수직으로 내려오는 오목한 곡선으로 바뀌어 패널 옆면과 꺾임 없이 이어집니다. 32%부터는 패널이 그 바닥에서 이어서 내려옵니다(처음에 빠르고 끝에서 길게 감속). 닫을 때는 0.26초에 같은 경로를 거꾸로 따라 패널이 노치 안으로 말려 올라간 뒤 노치가 원래 모양으로 돌아옵니다.
- 노치 관련 애니메이션은 WPF 기본 60fps 대신 주 모니터 주사율(60~240)로 그리며, 모니터 설정이 바뀌면 다시 읽습니다. 패널이 펼쳐지는 동안에는 패널 내용을 비트맵으로 고정해 프레임마다 다시 그리지 않습니다.
- 패널 바탕은 노치와 같은 검정이며 아래쪽 모서리만 반지름 16으로 둥급니다. 윤곽선이 노치에서 패널까지 한 줄로 이어집니다. 패널 높이는 최대 480이며 작업 영역 아래쪽에서 8 떨어집니다.
- 상세를 열면 목록 왼쪽에 틈 없이 같은 검정으로 붙고, 상세는 왼쪽 모서리만 둥급니다. 목록 가운데는 노치 가운데에 그대로 있고 창은 왼쪽으로만 넓어집니다.
- 패널에서 커서가 벗어나면 0.3초 뒤 닫힙니다. 고정 버튼으로 목록과 상세를 함께 고정할 수 있습니다. 패널을 읽는 동안 온 안내는 보류했다가 패널이 닫히면 보여 주며, 실제로 보인 때부터 표시 시간을 셉니다.
- 패널 하단의 **모두 읽기**는 현재 목록을 일괄 읽음 처리하고, **읽은 알림 삭제**는 읽은 항목만 목록에서 지웁니다. 삭제한 알림의 상세는 닫히며 대시보드 DB 기록은 유지됩니다.
- 알림 패널에는 집중 상태 표시·집중 전환 버튼을 두지 않습니다. 하단 홈 버튼으로 대시보드를 활성화하거나 최소화합니다.
- 노치와 패널을 클릭해도 작업 중인 창의 활성 상태를 가져오지 않습니다.

### 전체화면

- 전체화면 앱(영상, 슬라이드쇼, 게임 등)이 열리면 Windows가 AppBar에 보내는 알림(`ABN_FULLSCREENAPP`)으로 띠·노치·패널·안내를 모두 숨깁니다. 예약한 공간은 유지합니다. 알림 수집과 읽음·고정·상세 상태는 그대로 두고, 그동안 온 안내는 보류했다가 전체화면이 끝나면 보여 줍니다. 바탕화면 보기(Win+D)와 화면 캡처(Win+Shift+S)·시작 메뉴·검색·게임 바 같은 Windows 오버레이로 오는 같은 알림은 무시합니다.

### 로컬 확인이 필요한 항목

창을 끄는 동안 커서 가두기가 유지되는지(Windows 창 이동 처리가 덮어쓰지 않는지), Windows 11에서 창을 맨 위로 끌어 최대화·스냅하는 동작이 되는지, 띠 등록·해제 때 최대화한 창 크기 조정, 여러 배율(DPI)과 주사율, 작업표시줄을 위쪽에 둔 경우, 보조 모니터 전체화면, 앱 비정상 종료 뒤 위쪽 공간이 남는지, 패널을 여닫을 때 창 크기가 바뀌는 순간 깜빡임이 없는지.
