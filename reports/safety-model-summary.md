# base 안전 보강 결과

새 보강 원문 125개·375행을 추가하고 기존 base 체크포인트에서 이어 학습했다. 기존 가중치·데이터·평가 라벨·정책은 보존했다. 앱 모델 연결은 바꾸지 않았다. Qwen은 학습하지 않았다.

## 데이터와 학습

- 새 자료: `outputs/v10_safety_supplement_01/`.
- 현재 위험뿐 아니라 해결·과거·교육·허구·미래 점검, 일반 보안 확인, 암묵적 긴급도 3/4 경계를 포함한다.
- 원문 125개에 짧은 원형·접두·접미 변형 3개를 적용해 375행을 만들었다. 20자 이하 본문 35행, 최소 길이 11자다.
- 기존 긴급도 4,946행 전체와 관련도 점수별 500행(총 2,500행)을 재학습 자료로 유지했다.
- 보강 375행을 명시적으로 4회 반복하여 1에폭당 8,946행을 학습했다. 새로운 고유 데이터가 1,500개라는 의미는 아니다.
- Encoder LR 5e-6, head LR 2e-5, 유효 배치 16, FP16, 2에폭, 기존 5클래스 CE와 과제 간 총 기여도 균형을 사용했다. 임계값·통과 정책 변경은 없다.
- 학습 약 7.4분. 두 에폭의 선택 지표가 동일하여 첫 에폭을 선택했다.
- 별도 개발 평가 40행은 추론·학습 전에 원문과 라벨을 고정했다. 이전 평가 100행은 학습 또는 체크포인트 선택에 넣지 않았다.
- 학습·개발 본문의 정규화 정확 중복은 두 모델의 실제 두 과제 학습 자료, 기존 검증 74행, 이전 평가 100행과 비교해 배제했다. 의미 유사성이나 템플릿 수준의 독립성을 보장하는 검사는 아니다.
- 라벨은 기존 지침에 따른 AI 제안이며 사용자 보강 요청에 따라 학습했다. 인간 개별 검수 완료를 뜻하지 않는다.

## 남은 오류와 퇴행

- 기존 계약서 금액 오류 문장은 여전히 긴급도 4→3으로 내려간다. 무관한 창·빈 창의 2행을 차단한다.
- 기존 검증의 집중 음악 추천은 관련도 4→2로 내려 새로 차단했다. 기존 검증 전체에서는 무관한 자료의 오통과 2행이 줄어 총 정답이 1행 증가했지만 이 퇴행은 별도 관리해야 한다.
- 새 합성 평가의 일반 택배 도착 안내는 긴급도 2→4로 올라 새로 통과했다.
- 새 합성 평가의 가계부 중복 지출 수식 예제는 관련도 4→1로 내려 여전히 차단한다.
- 새 합성 평가의 일반 로그인 승인 확인은 긴급도 3→5로 올라 여전히 통과한다.

위 비교는 기존 합성 평가와 AI 제안 라벨 기준이다. 이전 100건의 실패 유형이 보강 분야 선정에 영향을 주었으므로 이번 결과는 회귀 진단이며 완전히 손대지 않은 최종 테스트가 아니다. 개발 평가 40건은 체크포인트 선택에 사용했으므로 독립 최종 평가 성능으로 해석하지 않는다. 97%는 실제 사용자 알림의 정확도를 뜻하지 않으며 긴급 누락 0건도 실전 무누락 보장은 아니다.

## 검증과 파일

- 필터링 테스트 35개 통과.
- 추가 학습 전 기존 체크포인트의 검증 67/74·긴급 누락 2건 재현.
- 새 FP32 ONNX가 선택 체크포인트의 원래 검증 74행 PyTorch 점수쌍과 모두 일치.
- 모델·토크나이저·기존 두 과제 학습 입력·기존 평가의 보호 SHA256 유지.
- 데이터·예측 수·고정 라벨 해시·문장별 전후 정책 개선/퇴행 확인.

실사용 후보 파일은 이 폴더의 `model-fp32.onnx`와 `tokenizer/`다. 입력 구성은 기존 `encoder_score_experiment.input_text`와 동일하다. `model.pt`는 추가 학습용 체크포인트다. 설정·학습 이력·에폭별 예측·비교 결과는 같은 폴더에 보관했다.

100건 전체 CPU 예측과 남은 오판은 `outputs/runs/2026-10-10-base-safety-personal-eval-01/review.md`에 있다. 현재 모델을 타인에게 시험 사용시키려면 원래 알림을 유지하고 판단만 기록하는 방식으로 실제 알림 자료를 먼저 모으는 것이 좋다.
